Leviathan Compute Revenue Mindmap

Quad-stream revenue architecture for off-grid GPU compute arbitrage

Revenue architecture

  • Passive income — GPU compute rack, Vast.ai, render networks, rent coverage
  • Active manufacturing — 3D printing, laser fabrication, vinyl graphics
  • Commercial mix — builds recurring and project-based revenue

Energy arbitrage

  • Generation-led — excess renewables become dump-load GPU demand
  • Price-led — cheap grid power, then monetize GPU margin
  • Rule — value only exists when generation and demand align

Net-positive gate

  • GPU revenue must exceed generation cost
  • GPU revenue must beat grid price if arbitrage is used
  • Load must fit the generation window
  • No new GPU debt should be absorbed by the model

Workload fit

  • Training — high $/kWh, bursty, higher margin
  • Rendering — steady and deadline-driven
  • Inference — always-on latency-sensitive workloads
  • Hashing — more commoditized, needs careful matching

Power ledger reality check

  • Baseline idle = 14.4 kWh/day
  • 8×400W + wind = 11.55 kWh/day average
  • Structural deficit remains present at every cycle
  • Viable path = full roof + deployables + throttling
  • Unproven — income vs hobby is still the core risk

Key insight

  • Transcript-sized system was first modeled at ~5 kWh/day
  • Later load assumptions moved to ~38.4 kWh/day
  • Those two numbers remain unreconciled
  • Hardware is still sized to the first number while load is based on the second
  • Full roof utilization is the biggest available win
